Connection to the process repository

Many companies already describe their processes, documents, controls and rules in Interfacing's Enterprise Process Center, the process repository. The audit module can take its requirements from there, and it writes the audit results back. This chapter is for companies that use both.

Requirements that already exist

A company that has mapped its processes has its rules written down already. Typing them in again as requirements doubles the work, and the two copies drift apart.

Requirement Management > Import & Sync Requirements with EPC Repository brings repository items in as requirements.

  1. One tab per kind of item: Import Control, Import Document, Import Process, Import Capability, Import Rule. Sync by Module updates requirements imported earlier.
  2. Folder: where in the repository to look.
  3. Tick items in the list and click Import Selected.
  4. Output reports what was imported.

Imported requirements appear in Create & Manage Requirements next to the ones typed in by hand. When you build a program, the tab Add new requirements from the repository picks them directly.

Results that flow back

The people who own a process want to see how it fared in the last audit, without opening the audit module.

After an audit is signed off, the product files the audit report in the repository and records the audit on each audited repository item. A CAPA's lesson learned and the evidence of each signed-off action item are archived there too.

Each kind of record goes to its own folder, set in QMS Settings (admin) > General Settings > EPC Settings. An empty folder setting means that kind of record is not archived.

Without a process repository

Cedar Valley typed its four requirements in by hand. That works for a company without a repository, or for rules that live outside it.

Everything in chapters 05 to 14 works without the repository. Leave the EPC Settings folders empty and use Create a Requirement.

Common mistakes

  • Importing a whole folder when only a few rules apply. The requirement list fills with items nobody audits.
  • Forgetting Sync by Module after the repository changes. The requirements keep the old wording.
  • Expecting archived results without setting the EPC Settings folders.
